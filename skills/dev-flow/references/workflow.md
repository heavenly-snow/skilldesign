# 共享契约

## 定位项目和轮次

产物写入目标项目。优先沿用项目现有文档目录及命名，并在轮次索引记录实际路径。默认在 `docs/dev-flow/轮次索引.md` 登记每轮 ID、业务标题、目录、状态（进行中或已完成）、基线和当前停点。每轮目录用 `rNN-英文短名`，分配下一个未用序号，已有 ID 保持稳定。批次编号在轮内独立，跨轮使用 `R02/B01`。存在唯一进行中轮次时可推断。多个候选无法区分时，展示候选和推荐，再由用户确认归属。

已存在的范围内返工留在当前轮。已验收之后的新增需求或独立验收修复进入新轮。新轮登记最相关的已验收产物与对应代码版本，记录继承项、变化项和影响范围。无变化的阶段可登记沿用版本、路径和理由。历史验收与产物保留在原轮。全轮约定范围获验收后，将索引记为已完成，登记可定位的提交、标签或交付版本。若尚无版本标识，记录待补的定位依据。

索引可用一张表，列为轮次、标题、目录、状态、基线和停点。设计阶段也要在产物生成或讨论结果落盘后更新停点，写明阶段、产物路径及下一步。跨轮路径和版本应足以重新找到验收时使用的文件。

## 设计产物

默认命名依次为 `00-需求材料.md`、`01-PRD.md`、`02-架构设计.md`、`03-产品原型.md`、`04-数据库设计.md`、`05-接口设计.md`。原型文件默认放在 `03-原型/`，也可引用项目现有入口。需求材料文件登记来源、原文或外链。设计文档写明轮次、前序产物、决定、待决项及讨论结论。用相对链接和稳定的决策或操作编号关联相关章节。当前轮内直接更新对应文件。

**设计时显式参考全部已形成的前序产物**，包括本轮登记的继承依据。优先使用确认版本。缺失、不可读或冲突时标明具体影响。可以先做不依赖该决定的部分，实质歧义先给出初判和建议再讨论。

**开发时资料选择由执行 Agent 决定**。批次定义交付范围和验收条件。Agent 自行检索项目和设计资料，并记录影响实现的实际依据。

## 批次状态

每轮使用一份 `开发批次.md`。基础设施默认 `B00`，业务批从 `B01` 开始。执行前确认依赖和范围已具备。计划已讨论的批次可直接按用户指令执行。后续调整保留 ID，更新受影响的依赖和验收条件。

计划状态为「初稿」或「已讨论」，另记计划讨论结论。初稿里的待执行只表示尚未开始。恢复初稿时，展示计划和待讨论点。只有计划已讨论，或用户看过初稿后明确指示按它执行目标批，才能开始该批。后者将指令记为目标批的讨论结论。业务批通常依赖 B00 已通过，其他依赖按计划核对。证据应标明对应的改动版本或范围，修改相关代码后重新验证受影响的结论。

依赖未满足时，保留目标批为待执行，展示具体缺口和推荐的下一步。若批次范围或验收条件尚未细化，由 AI 补出初版并显式展示。用户明确要求执行的现有批次，如补充内容改变已讨论范围，先讨论差异。每批只推进自己的状态，保留其他批次已有的记录。

- **待执行 → 进行中**：收到执行指令，检查依赖。
- **进行中 → 待讨论**：发现实质冲突。保存冲突依据、推荐方案、影响与可继续的部分。讨论后记录结论，再恢复本批或调整计划。
- **进行中 → 待验收**：提交证据、复验方式、遗留问题与 AI 建议。停止跨批推进。
- **待验收 → 已通过 / 进行中**：按验收讨论结论落盘。接受则已通过，返工则回本批执行。未通过的批次仍阻塞其依赖方。

每次状态切换及中断前同步批次文件和轮次停点。验证结果区分通过、失败、未执行。用户未接受的结论仍记为待讨论或待验收。批次状态是可复核的记录，由 Agent 按规则维护。
